Пачка API-ключей от разных LLM-шлюзов и агрегаторов? Каталог обещает 300+ моделей — но какие реально отвечают, какие падают с ошибкой, а какие устарели и никогда не пригодятся? **tg-api-checker** пробит каждую модель (или выборку), покажет точные HTTP-ошибки и причины rate-limit, ведёт зашифрованную историю ключей и позволяет искать по всему, что когда-либо проверялось — прямо в Telegram.

## Возможности

- **Вставляй что угодно** — голый ключ, `URL + ключ`, целый пересланный отчёт другого чекера. Парсер извлечёт пару; если в сообщении два *разных* адреса или ключа, бот спросит уточнение, а не отправит твой ключ на чужой сервер. Адреса без `https://` работают.
- **Пробы моделей с реальными ошибками** — HTTP 200 с пустым текстом не считается успехом; 401/403/423/429 получают понятные причины + текст ошибки сервера (ключ скрывается).
- **Фильтр версий до траты баланса** — Claude 5+, GPT 6+, Gemini 4+, GLM только 5.3.x; MiniMax/Kimi — свежайшая версия из каталога. Правила в одном файле. Пропущенные модели перечислены с причинами.
- **Зашифрованная история ключей** — ключи и результаты в SQLite под Fernet; `vault.key` хранится отдельно от базы. Перепроверка в один тап, без повторной вставки ключа.
- **Полные прогоны каталога со стопом/продолжением** — каждая проба сохраняется; прерви прогон на 300 моделей и продолжи позже (после перезапуска — вручную, автоматически баланс не расходуется).
- **Адаптивный тротлинг** — старт на 10 параллельных запросов; первый 429/423 с признаком параллельности переводит на по одному с паузой 5 с. Ошибка одной модели не останавливает каталог.
- **Мультипротокольность** — Chat Completions, Responses, Anthropic Messages, Gemini generateContent. Формат подбирается одним зондом; ошибки авторизации/квоты не запускают перебор. На родных хостах Anthropic/Gemini каталоги берутся из их API.
- **Поиск по архиву** — `/find opus 5.5` по всем сохранённым каталогам; `--check` — проверить только найденное. Результат в том же сообщении с кнопками перехода.
- **Пакеты** — до 50 пар, одно живое сообщение статуса, отчёты по каждому ключу в один тап.
- **Честная телеметрия** — баланс DeepSeek и квота OpenRouter показываются, если провайдер их раскрывает; иначе в отчёте «не раскрываются». Бот не выдумывает числа и не заявляет подлинность модели за прокси.

## Запуск

```bash
git clone https://github.com/juzorei/tg-api-checker.git
cd tg-api-checker
python -m venv .venv && .venv\Scripts\activate   # Windows (Unix: source .venv/bin/activate)
pip install -r requirements.txt
copy .env.example .env                            # вписать BOT_TOKEN от @BotFather
python bot.py
```

 пришли боту base URL и ключ. Готово — отчёт придёт ответом на твоё сообщение.

Необязательные переменные: `MAX_CONCURRENT_TESTS` (1–20, по умолчанию 10), `MAX_MODELS_PER_RUN` (500), `MAX_OUTPUT_TOKENS` (128), `ALLOWED_USER_IDS` (список Telegram ID через запятую).

## Команды

| Команда | Что делает |
|---|---|
| *(вставить URL + ключ)* | Полный чек: каталог, пробы выборки, лимиты — ответом на сообщение |
| `/keys` | История: перепроверка, полный прогон, фильтры, повтор ошибок, TXT, заметки, удаление |
| `/batch` | Собрать до 50 пар и прогнать с одним статусом |
| `/find <запрос> [--check]` | Поиск по всем каталогам; `--check` — проверить найденное |
| `/cancel` | Отмена ввода, пакета или идущей проверки (текущий запрос может завершиться) |

## Безопасность

- Ключи **зашифрованы при хранении** (Fernet) и не попадают в `callback_data`, логи и тексты ошибок — сообщения об ошибках сервера чистятся от ключа перед показом.
- Транспорт блокирует loopback/private/link-local адреса на момент соединения (проверяется DNS-ответ, не только разбор URL), не следует redirect и не использует proxy из окружения.
- История строго привязана к Telegram ID; записи других пользователей недоступны.
- ⚠️ В отчётах ключи показываются полностью для копирования — **не пересылай отчёты**. Удаление из истории не стирает старые сообщения Telegram.
