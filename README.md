# tg-api-checker

Telegram-бот проверки OpenAI-совместимых и нативных AI API в личном чате: каталог моделей, проверка доступности, лимиты, история ключей, поиск моделей по архиву. Пробы могут расходовать баланс. Бот не устанавливает подлинность модели за прокси.

Поглощает функциональность [tg-model-checker](https://github.com/juzorei/tg-model-checker) (проверка моделей кнопкой «Диагностика»).

## Запуск

Python 3.12: `python -m venv .venv`, активировать окружение, `pip install -r requirements.txt`. Скопировать `.env.example` в `.env`, вписать `BOT_TOKEN` от [@BotFather](https://t.me/BotFather). Запуск: `python bot.py`.

Переменные окружения: `MAX_CONCURRENT_TESTS` (1–20, по умолчанию 10), `MAX_MODELS_PER_RUN` (500), `MAX_OUTPUT_TOKENS` (128), `ALLOWED_USER_IDS` (необязательный список Telegram ID через запятую).

## Использование

- **Проверка ключа:** отправь base URL + ключ одной строкой или вставь текст отчёта целиком (адрес без `https://` тоже распознаётся). Отчёт приходит ответом на твоё сообщение. Два разных адреса или ключа в одном сообщении — запрос уточнения: ключ не отправится не на тот сервер.
- **`/keys`** — история пар: отчёт, перепроверка, полный чек, стоп/продолжение, фильтры (рабочие/ошибки/непроверенные/пропущенные), повтор ошибок, TXT рабочих моделей, заметка, удаление с подтверждением.
- **`/batch`** — до 50 пар отдельными сообщениями, затем «Проверить всё». Одна обновляемая сводка.
- **`/find opus 5.5`** — поиск по всем сохранённым каталогам буквально; `--check` — сразу проверить найденные пары. Результаты в том же сообщении.
- **`/cancel`** — отмена ввода, пакета или запущенной проверки (текущий запрос может завершиться).

## Протоколы и каталоги

Форматы: OpenAI Chat Completions, OpenAI Responses, Anthropic Messages, Gemini generateContent. При проверке бот зондирует формат по одной модели (сначала сохранённый); ошибка авторизации/квоты не считается несоответствием протокола и не запускает перебор. Ручной выбор — кнопкой «Формат API». Для нативных Anthropic/Gemini каталог берётся из их собственного /models до OpenAI-совместимого.

## Фильтр версий

До отправки запросов применяются правила: Claude/Opus/Sonnet/Haiku 5+, GPT 6+, Gemini 4+, GLM только 5.3.x; MiniMax M и Kimi K — максимальная числовая версия в каталоге данного API (включая варианты одной версии). Это сравнение ID, не оценка качества. Неизвестные версии, GPT-OSS и прочие семейства сохраняются. Полный каталог не удаляется; кнопка «Пропущенные» показывает причины.

## Тротлинг

Первая порция — до N параллельных запросов. После 429/423 с признаком параллельности — один запрос за раз с паузой 5 с. Ошибка одной модели не останавливает каталог; подтверждённая проблема ключа не провоцирует перебор протоколов. Задания сохраняют каждую пробу и продолжаются с места остановки (после перезапуска — вручную).

## Хранилище

`data/history.sqlite` — записи с привязкой к Telegram ID; ключи и результаты зашифрованы Fernet, `data/vault.key` хранится отдельно от базы; оба файла исключены из Git. URL и заметки не зашифрованы. Потеря vault.key делает записи нечитаемыми; при существующей базе секрет автоматически не создаётся. Перенос — оба файла целиком; резервные копии тоже защищать. Windows: ограничить ACL каталога data; Unix: `chmod 700 data`. Шифрование не защищает от доступа с правами владельца машины. В отчётах ключи показываются полностью — не пересылай отчёты. Удаление из истории не стирает сообщения Telegram.

## Безопасность сети

Сетевой слой блокирует непубличные адреса при установке соединения (loopback, private, link-local), проверяет DNS-ответы, не следует redirect и не использует proxy из окружения. Это не SSRF-защита общего назначения: используйте только с доверенными API и не публикуйте бота как общедоступный сервис без изоляции.
